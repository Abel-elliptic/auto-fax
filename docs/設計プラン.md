### 送信画面の自動操作（実装：faxjob/sender_gui.py）
- uidump（2026-11-13）で取得した部品 ID を使用（FF Direct Fax Driver 3.3.9.1）。
  - 「ファクス送信の設定／確認：<文書名>」：送信開始=1、送信中止=2、宛先の一覧=4002、一覧に追加=4003、宛先種別=4016、宛先番号=4018、名前=4019、宛先表から追加=4049、時刻指定=4010

  - 宛先表には「一斉2」(Group, 34件) と「一斉」(Group, 44件) が別にある → **名前の完全一致＋(Group) の両方で1件に絞る**。

### 用語：「印刷」について（紙は出ない）
このプランで「印刷」と書いている処理は、**紙に印刷することではない**。Windowsの仕組みでは、ダイレクトファクスは「FAXドライバーというプリンターに出力する」形で動く。
データは PC → (LAN) → 複合機 → 電話回線 → 相手先 と流れ、**PC側でも複合機側でも紙は出ない**（公式FAQ：「パソコン(Windows)から直接ファクス送信できます」）。
ドライバーを通さずにファイルを直接FAX送信する方法（API・コマンド・IPPファクス等）は、公式情報で**確認できていない（未確認）**ので、F-4で調査対象として残す。

```
   ├ 照合・検証             … 拡張子/マスタ/安定性チェック
   ├ レンダリング           … pypdfium2(PDF→画像) + Pillow(画像整形・モノクロ化)
   ├ 印刷                   … pywin32(win32print/win32ui, DEVMODEで用紙・方向指定)
   │                          → プリンター「ART EX ダイレクトファクス（Apeos C2360）」
   └ 状態管理               … SQLite（送信履歴・二重送信防止）+ テキストログ
        │ LPR/IPP等（ドライバーのポート設定に従う）
[Apeos C2360] ダイレクトファクス → 電話回線 → グループ「一斉2」
        │ 簡易ログ転送(SMB) / ジョブ履歴
[C:\FAX\結果] ← 送信結果の照合に使用（使える場合）
```
- ※FAXドライバーが送信時にダイアログを出す場合、**ユーザーセッション外（ログオフ状態）ではGUIが表示できず失敗**するため、「ユーザーがログオンしているときのみ実行」が前提になる可能性が高い（要検証）。
- 技術選定：PowerShellでもGDI印刷は可能だが、PDFラスタライズ・画像処理・DEVMODE操作をまとめて書けるPythonを推奨。PDFライブラリは商用利用で問題になりにくい pypdfium2（Apache-2.0/BSD）を候補（PyMuPDFはAGPL）。

## C. 処理フロー

```
起動 → 多重起動ロック取得(処理中\.lock) → 前回中断ジョブの復旧チェック
 → 送信\ の一覧 → 拡張子判定(.pdf/.jpg/.jpeg/.png, 大小無視)
   ├ 対象外 → ログ記録・放置（送信しない）
 → 拡張子除去名でマスタ照合 ──未登録→ ログ記録・放置
 → 安定性チェック（サイズ/更新時刻を数秒おいて2回比較、排他オープン可否）──NG→ 次回へ
 → SHA-256算出 → 送信履歴に同一ハッシュ+同一名の「送信済」あり → 二重送信としてスキップ
 → 処理中\ へ移動（ジョブID付与, 状態=PREPARED をDB記録）
 → レンダリング（A4/A3・縦横、モノクロ）→ プレビューPNG保存
 → FAXドライバーへ印刷投入（状態=SPOOLED）
 → 送信結果確認（簡易ログ転送ファイル/ジョブ履歴を照合、タイムアウトあり）
   ├ 成功確認 → 送信済\YYYYMMDD\ へ移動, 状態=SENT
   ├ 失敗確認 → エラー\ へ移動, 状態=FAILED（ファイルは削除しない）
   └ 確認不能 → 状態=UNCONFIRMED, 処理中\ に保持し人が確認（自動再送しない）
 → 実行サマリをログ出力 → ロック解放
```

## D. ファイル名別設定マスタ
- 形式：`C:\FAX\設定\master.csv`（UTF-8 BOM付き。Excelで編集可能）
  `ファイル名,用紙サイズ,印刷方向,有効` 例：`請求書,A4,縦,1`
- 起動時に検証：用紙∈{A4,A3}、方向∈{縦,横}、ファイル名重複なし、Windows禁止文字なし。1件でも不正ならその行は無効扱いでログ（全体停止はしない）。
- 照合：`Path.stem` を Unicode NFC 正規化し**完全一致**（前後空白は不一致として扱う）。拡張子は `.lower()` で判定。`請求書_控え.pdf` は別名として未登録扱い。
- 同一stemで複数拡張子が同時に存在：**1つだけ送る。優先順位 PDF > JPEG(.jpg/.jpeg) > PNG**（ユーザー決定）。送らなかった側は「同名重複のため未送信」とログに残し、送信\ に残す。.jpg と .jpeg が同時にある場合は、どちらを送るか決められないため両方エラー扱い（要確認事項としてレポートに表示）。

## E. PDF・画像の印刷処理
- 方式：全形式を**モノクロ画像に変換してから印刷**（FAX解像度に合わせ、挙動を一定にするため）。
- 用紙：A4=210×297mm, A3=297×420mm。方向「横」は幅高さを入れ替え。
- 余白：既定 各辺5mm（設定可能）。プリンターの印刷可能領域（GetDeviceCaps PHYSICALOFFSET）を取得し内側に配置。
- 拡大縮小：「余白内に収まる最大倍率で縦横比維持・中央配置」（fit）。
- **PDFの向き・サイズ（ユーザー決定）**：PDFは通常の印刷と同じく、**各ページ自身のサイズ・向きを読み取ってそのまま使う**（ページの /Rotate を反映した見た目の縦横で判定）。
  - ページが縦長→縦、横長→横。用紙はページ寸法に近いA4/A3を選ぶ（A4以下→A4、A4超〜A3→A3、A3超→A3に縮小）。
  - マスタの用紙・方向は、PDFでは「想定値」として扱い、**PDFから読み取った値と違う場合はデモ画面とログに警告表示**（送信は止めない）。マスタの値を優先させる切替を settings.toml に用意（`pdf_layout = "auto" | "master"`、既定 auto）。
  - 実際にFAXドライバーで「PDFどおり」になるかは、Step2〜3のテスト環境で確認してから本番に進む。
- 画像（JPEG/PNG）：画像にはページサイズ情報が無いので、マスタの用紙・方向を使う。回転はせず縦横比維持で中央配置。
- PDF：全ページ送信。サイズ混在もページごとに上記判定を行う。
- 解像度：レンダリング 200dpi（FAXの「高画質」相当を想定）→ 実機で 200/300/400 を比較。
- モノクロ化：グレースケール→ 文字主体はしきい値二値化、写真主体はディザ（Floyd–Steinberg）。マスタ列に `画質モード(文字/写真)` を追加可能。
- 画像：EXIF回転を補正、透過PNGは白背景で合成。
- **デモ用**：各ページのプレビューPNGと、元ファイル・マスタ設定・倍率を一覧するHTMLレポートを `C:\FAX\ログ\preview\` に出力（送信はしない）。

## F. FAX送信処理（最重要・要実機検証）
優先順で検証し、最初に無人で安定動作した方式を採用する。
1. **ドライバー既定値方式**：ドライバーのプロパティ（初期設定タブ等）で宛先「一斉2」（本体宛先表のグループ）を既定値にし、送信確認・宛先再入力ダイアログを無効にできるか確認 → できればGDI印刷だけで無人送信。（公式に「ファクス宛先の再入力」をしない設定の記述はあるが、宛先自体を省略できるかは**未確認**）
2. **メーカー問い合わせ**：富士フイルムBIサポート／販売店に「ダイレクトファクスのコマンドライン・SDK・宛先自動指定」の可否を書面で確認。
3. **GUI自動化方式（代替）**：pywinauto で宛先ダイアログを操作（宛先表→一斉2→送信）。制約：ログオン中のデスクトップが必要、画面ロック/解像度変更/ドライバー更新で壊れやすい、UI文言依存。スクリーンショットをログに残す。
4. 補助案（未確認・調査のみ）：IPP Class Driver 経由のFAX、複合機側の機能（ボックス・ジョブフロー等）による送信。
- 送信完了の確認：ドライバー投入成功（スプール完了）≠送信完了。**「簡易ログ転送」でSMB共有へ届く送信文書ファイル**、または**インターネットサービスのジョブ履歴**を照合して完了判定。どの情報（成否・相手・時刻）が取れるかは実機で確認し、取れない場合は「UNCONFIRMED＋通信管理レポートで人が確認」とする。

## G. エラー・ログ管理
- 状態DB（SQLite `C:\FAX\設定\state.db`）：job_id, ファイル名, SHA-256, マスタ設定, 状態(PREPARED/SPOOLED/SENT/FAILED/UNCONFIRMED), 時刻, 結果根拠。
- 二重送信防止：①多重起動ロック、②同一ハッシュの SENT/SPOOLED/UNCONFIRMED があれば送らない、③処理中\ への移動を送信前に行う。
- 中断復旧：起動時に 処理中\ と DB を照合。PREPARED→送信前なので再処理可。SPOOLED/UNCONFIRMED→**自動再送しない**（送信済の可能性があるため）。人が確認後、`retry` コマンドで 送信\ へ戻す。
- 再送：自動再送は行わない方針を既定とする（同報先への重複送信の害が大きいため）。複合機自体のリダイヤル設定は本体側に任せる。
- ログ：日次ローテーションのテキストログ＋CSV送信履歴（Excelで閲覧可）。

## H. 導入手順
